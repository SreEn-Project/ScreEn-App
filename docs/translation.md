# 번역 기능

번역 파이프라인의 현재 구현, 캐시 방침, 속도 · 정확도 개선 계획. 결정의 이유는 [decisions.md](decisions.md) (D-030 · D-031 · D-036).
코드: `android/.../translate/`, `ocr/`.

## 현재 구현 (한 번 번역할 때)
1. **캡처**: 한 프레임. 영역이면 잘라낸다.
2. **문자 인식** (`ScreenTextRecognizer`): 긴 변 2000px로 줄여 ML Kit로 읽는다.
   - 자동 모드는 직전에 이긴 문자(처음 한국어) 하나로 먼저 읽고, 12자 미만이거나 신뢰도 0.8 미만이면 한 · 일 · 중 · 라틴 후보를 병렬로 돌려 가장 잘 읽은 것을 쓴다.
   - 글자가 12자 미만이면 색을 뒤집어 한 번 더 읽는다.
   - 읽은 뒤 `OcrTinyTextFilter`로 화면에 견줘 아주 작은 줄 · 짧은 라틴 조각을 거른다 (#178).
   - 입력 이미지 해시가 직전과 같으면 인식을 건너뛴다.
   - 자동 번역은 직전 화면과 격자를 견줘 바뀐 영역만 다시 읽는다 (`ChangedRegions`, #43). 바뀐 칸이 없으면 이전 결과를 쓰고, 40% 넘게 바뀌었거나 영역이 많으면 통째로 읽는다.
3. **정리**: `OcrCleaner`(잡음 줄 제거) → `OcrPostProcessor`(오인식 보정, #45) → `OcrBlockMerger`(이어지는 블록을 문단으로). 줄바꿈 · 줄 끝 하이픈은 이어 붙인다.
4. **언어 판별**: 한글 30% 이상이면 ko, 가나면 ja, 아니면 Language ID. 원문 = 대상이면 건너뛴다.
5. **번역**: 블록마다 ML Kit 온디바이스 번역을 동시에 돌린다 (`TranslationEngine` 인터페이스).
6. **표시**: 모든 블록이 끝난 뒤 한 번에 목록 · 문단 · 원문 위 덮기로 보여 준다.

## 캐시
- 파이프라인(`BlockCache`)에 블록(원문 글자) 단위 LRU 512개 둘: 언어 감지 결정, 번역 결과. 번역 키는 (엔진, 원문, 원문 언어, 대상 언어). 성공한 번역만 넣는다. 메모리에만 있어 서비스가 끝나면 사라진다.
- ML Kit 엔진 안에도 128개짜리 캐시가 있어 중복이다 → AI 엔진 전에 정리한다.
- AI 엔진이 붙으면 키에 모델 · 프롬프트 버전을 넣는다 (품질을 바꿔도 옛 번역이 나오지 않게).
- 디스크 영구 캐시는 하지 않는다 (효과 작음, 화면 글자를 저장하는 개인정보 부담). 하게 되면 Room + 보관 기간 제한.
- 캐시는 속도에만 도움이 된다. 잘못 번역된 결과가 고정될 수 있어, 사용자가 다시 번역하면 그 항목은 캐시를 무시하는 방안을 검토한다.

| 2 | ✅ 점진 표시 (#41) | 수동 번역은 번역이 끝난 블록부터 먼저 보여 주고 마지막에 전체 결과로 바꾼다. 자동 번역은 표시 시점 규칙(D-036)을 지키려고 제외. |
| 3 | ✅ 바뀐 영역만 다시 인식 (#43) | 자동 번역에서 직전 화면과 밝기 격자를 견줘 변한 칸 주변만 잘라 읽고 안 바뀐 블록은 재사용. 많이 바뀌면 전체 인식. 기기 실측 전. |
| 4 | ✅ 인식 후처리 (#45) | `OcrPostProcessor`: 글자 사이에 낀 0·1·5·|와 소문자 사이 I를 글자로, 숫자 사이 O·l을 숫자로, 문장 첫머리 l'm·`| am`·lt를 I'm·I am·It로, 합자(ﬁ 등) 풀기, 줄 전체가 짧은 UI 단어(OK · Cancel · Settings 등 영어 약 70개)면 사전으로 바로잡기. 주소 · 파일 이름 · 코드 조각과 한·중·일 글자는 건드리지 않는다. 영어(라틴)만. 기기 실측 전. |
| 진행 | AI 번역 (3단계, #94) | `GeminiTranslationEngine`(REST) + `FallbackTranslationEngine`(오류 · 오프라인 · 키 없음이면 ML Kit)까지 완료. **BYOK 결정(사용자가 본인 Gemini 키를 입력, #96)**: 설정 > AI 번역 설정에서 키를 붙여 넣으면 `ApiKeyStore`(Android Keystore AES-GCM)에 암호화해 기기에만 저장하고, 키가 있어야 Gemini 엔진을 고를 수 있다. 키를 지우면 ML Kit으로 되돌린다. 남은 것: ML Kit 먼저 보여 주고 AI로 교체, 블록 묶어 1회 호출, 캐시 키에 모델 · 프롬프트 버전(`PROMPT_VERSION`). 주의: 대체된 ML Kit 결과가 Gemini 키로 캐시된다. **옵션(#118, D-049)**: 만 18세 확인 후에만 Gemini 사용, 말투(존댓말 · 반말)와 용어집(글에 나온 항목만)을 프롬프트에 넣고 캐시 키에 포함. |

## Groq 엔진 (NA-13, #167, D-066)
Gemini와 같은 BYOK 방식의 두 번째 AI 엔진. 공식 문서 확인일 2026-10-08.
- **연령**: Groq Services Agreement — "You must be 18 years of age or older to access or use the Cloud Services." → Gemini와 같은 만 18세 확인(FL-09) 적용.
- **무료 한도**: 무료 플랜이 있고 모델별 분당 · 일일 요청 / 토큰 제한이 있다. 정확한 수치는 계정의 Limits 페이지에서만 확인되고 문서 표(console.groq.com/docs/rate-limits)에는 Llama 모델이 없다. 초과하면 429 → "AI 한도 초과" 안내 후 ML Kit으로 대체. 무료/체험 서비스는 AS IS이며 변경 · 중단될 수 있다.
- **데이터**: 번역할 글자가 Groq로 전송된다(DPA 적용). 설정의 데이터 전송 고지에 Groq를 포함했다.
- **모델**: `llama-3.3-70b-versatile` 우선, 없으면 `llama-3.1-8b-instant`. 한국어 번역 품질은 70B가 안정적이어서.
- **호출**: `POST https://api.groq.com/openai/v1/chat/completions`, 헤더 `Authorization: Bearer <키>`, system(번역 지시) + user(원문), `temperature 0`. 단어 사전은 `response_format: json_object`.

## AI 응답 검증 · 묶음 호출 · ML Kit 먼저 표시
- **ML Kit 먼저**: AI 엔진(Gemini · Groq · Gemma)을 쓰면 `TranslationPipeline.translateWithPreview`가 AI와 ML Kit을 동시에 시작하고, ML Kit이 먼저 끝나면 그 결과를 먼저 보여 준 뒤 AI 결과로 바꾼다. AI가 먼저 오면 미리 보기는 건너뛴다. 미리 보기는 AI 캐시에 들어가지 않는다.
- **묶음 호출**: Gemini · Groq는 화면의 블록을 (원문 언어, 대상 언어, 말투)별로 요청 한 번에 보낸다. 입력은 JSON 문자열 배열, 출력은 `{"translations":[...]}`로 고정(`BatchTranslation`). 개수가 안 맞거나 형식이 틀리면 그 묶음만 블록별 호출로 되돌린다. Gemma는 기기 안에서 도는 작은 모델이라 블록별로 둔다.
- **응답 검증**: `GuardedTranslationEngine`(`AiResponseGuard`)이 모든 AI 엔진 결과를 검사한다. 대답 문장("번역해 드릴게요"), 프롬프트 지시문, 대상 언어 글자 없음, 길이가 크게 어긋남, 원문 그대로이면 버리고 다음 엔진 → ML Kit 결과를 쓴다. 원문을 다시 보여 준 줄은 지운다.
- 프롬프트에 "원문을 다시 보여 주지 말고 번역만"을 명시했다 (`PROMPT_VERSION` 3, 캐시 키가 바뀐다).
