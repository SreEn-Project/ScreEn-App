## D-017 · 2026-09-29 · 서비스 시작 흐름 (NA-02 · NA-03 · NA-04 일부)
Android 14+는 mediaProjection 포그라운드 서비스를 캡처 동의 **뒤에만** 시작할 수 있어 NA-02 · NA-03과 NA-04의 동의 부분을 함께 만든다.
- 흐름: Flutter `startService()` → 투명 `CaptureConsentActivity`(상태 STARTING) → 동의 창 → 허용: `TranslatorService` 시작(startForeground → getMediaProjection, RUNNING) / 거부: STOPPED.
- 동의 창은 Android 14+에서 기본이 "앱 하나 공유"라 `MediaProjectionConfig.createConfigForDefaultDisplay()`로 전체 화면을 요청.
- 동의 Activity를 따로 둔 이유: 앱 화면 · 알림 · 빠른 설정 타일(NA-25) 어디서 시작해도 같은 경로. FlutterActivity와 분리.
- 토큰은 한 번만 쓸 수 있어 `START_NOT_STICKY`. 시스템이 공유를 끄면(MediaProjection.Callback.onStop) 서비스도 멈춘다.
- 상태에 ERROR 추가 (FL-03 명세의 "오류"). 다시 시작하면 벗어난다.
- 알림: 채널 IMPORTANCE_LOW(조용히), 누르면 앱 열기, "중지" 동작. 네이티브 문구는 `res/values(-ko)/strings.xml`, 색은 `res/values/colors.xml`(design 토큰과 같게).

## D-018 · 2026-09-29 · 클린 아키텍처 (D-010의 Flutter 부분 대체)
사용자 요청: MVVM만으로는 구조가 지저분해 보임 → 클린 아키텍처 적용.
- 의존 방향 presentation → domain ← data. domain은 순수 Dart(freezed_annotation만 허용).
- domain: 엔티티(앱 자체 열거형 — Pigeon 열거형을 쓰던 D-010을 바꿈), 리포지토리 인터페이스, 유스케이스(동작 하나당 클래스 하나, `call()`; 공통 규약 `core/domain/use_case.dart`).
- data: 데이터소스(Pigeon · permission_handler 감싸기), 매퍼(Pigeon ↔ 엔티티), 리포지토리 구현. Pigeon 타입은 data 밖으로 안 나감.
- presentation: screens / view_models / widgets. ViewModel은 유스케이스만 호출.
- DI: 기능마다 `di.dart`에 Riverpod provider(데이터소스 → 리포지토리 → 유스케이스). 전용 DI 패키지(get_it 등)는 쓰지 않음 — Riverpod이 이미 DI와 테스트 override를 해 줌.
- 규칙은 `test/architecture_test.dart`로 검사 (첫 실행에서 도메인이 Flutter를 import하던 곳 1건을 잡아 고침).
- 네이티브(Kotlin)는 이미 bridge / service / data 로 나뉘어 있어 이번에는 바꾸지 않음.

## D-019 · 2026-09-30 · 프레임 캡처 방식 (NA-05)
- 세션 시작 때 VirtualDisplay(AUTO_MIRROR) + ImageReader(RGBA_8888, 버퍼 2)를 만들고 세션 동안 유지. Android 14+는 토큰 하나로 VirtualDisplay를 한 번만 만들 수 있다.
- 미러링은 화면이 바뀔 때만 프레임을 보내므로, 들어오는 최신 프레임 하나를 **계속 들고** 있다가 요청 때 Bitmap으로 바꾼다 → 멈춘 화면도 바로 찍힘.
- 회전: Android 14+는 `onCapturedContentResize`에서 resize(시스템이 알려 준 크기), 13 이하는 설정 변경 때 VirtualDisplay를 새 크기로 다시 만든다 (13에서 resize는 비율이 어긋나는 것을 에뮬레이터에서 확인).
- 전부 검은 프레임(밝기 ≤ 8, 24×24 표본)은 Blank → 보안 화면 안내에 쓴다.
- 디버그 빌드에만 알림 "캡처 테스트" 동작(앱 캐시에 PNG 저장). 플로팅 버튼(NA-18)이 생기면 캡처 전에 오버레이를 숨긴다.

## D-020 · 2026-09-30 · 문자 인식기 고르기 (NA-09) — 사용자 확인 필요

## D-024 · 2026-10-01 · 오버레이 구조 (NA-18, NA-19)
- **Compose로 그린다** (foundation만, Material 컴포넌트 없음 — 모양은 `overlay/OverlayComponents.kt`에 Flutter `core/ui`와 같게). 창마다 WindowManager `TYPE_APPLICATION_OVERLAY` + 자체 Lifecycle · SavedState 주인(서비스에는 Activity가 없음).
- 창 4개: 플로팅 버튼(포커스 없음), 닫기 영역(끄는 동안만, 터치 안 받음), 모드 메뉴(버튼 옆 WRAP 창, 바깥 터치로 닫힘), 결과 시트(전체 화면, 포커스를 받아 뒤로 가기로 닫힘).
- 버튼 제스처는 Compose가 아니라 View 층에서 화면 좌표(rawX/Y)로 처리 — 창이 손가락을 따라 움직여 창 기준 좌표가 흔들리기 때문. 놓으면 가까운 좌우 가장자리에 붙고 시스템 막대는 피한다(`OverlayGeometry`, 순수 로직 · 단위 테스트).
- 캡처: 버튼을 숨김(INVISIBLE) → 숨긴 뒤의 새 프레임을 기다림(최대 200ms, 이어서 50ms 안의 프레임 하나 더) → 찍고 곧바로 다시 보임 + 번역 끝날 때까지 도는 링. D-019의 "최신 프레임을 들고 있는" 방식이라 기다리지 않으면 버튼이 찍힌다.
- ~~1단계는 전체 화면만~~ → D-027에서 드래그 지정 · 고정 영역 · 고정 영역 편집이 연결됨.
- 닫기 영역에 놓으면 서비스 종료(알림 "중지"와 같음). 버튼 위치는 프로세스 안에서만 기억(표시 설정 FL-07 때 저장 검토).
- 결과: 블록마다 줄을 이어 한 문단으로 만들어(ja · zh 등은 공백 없이) 엔진에 동시에 요청. 모두 실패하면 목록 대신 이유(Wi-Fi 필요 · 저장 공간 · 모델 없음)를 안내하고, 일부만 실패하면 그 카드에 "번역하지 못했어요". 미지원 언어는 원문 + 안내.
- 복사: 카드별 번역문, 전체 복사는 빈 줄로 잇는다. "AI로 다시 번역"은 ML Kit 결과일 때 비활성으로 보이고 NA-13에서 연결.
- 엔진은 서비스가 `MlKitTranslationEngine` 하나를 세션 동안 가진다(설정 엔진과 무관, AI 엔진이 생기면 고르기 · 대체).
- 다크 모드: `res/values-night/colors.xml` (design.md 다크 열).
- 다른 앱 위 표시 권한이 없으면 버튼을 띄우지 않고 서비스만 돈다 (권한 화면이 시작 전에 막는다).

## D-025 · 2026-10-01 · 오버레이 아이콘은 Material Symbols 부분 글꼴
Flutter와 같은 Material Symbols Rounded 선 아이콘을 쓰되, 원본 글꼴(15MB) 대신 쓰는 글자만 남긴 3.4KB 글꼴 `res/font/material_symbols_rounded.ttf`를 넣는다. 코드포인트는 `overlay/OverlayTheme.kt`의 `Symbol`.
아이콘을 추가할 때 다시 만드는 법 (fonttools, 원본은 pub 캐시 `material_symbols_icons/lib/fonts/MaterialSymbolsRounded.ttf`, 코드포인트는 같은 패키지 `symbols.dart`):
```
pip install fonttools
pyftsubset MaterialSymbolsRounded.ttf --unicodes="U+e5d0,U+e3be,..." --layout-features='' --no-hinting --output-file=sub.ttf
python -c "from fontTools.ttLib import TTFont; from fontTools.varLib import instancer; instancer.instantiateVariableFont(TTFont('sub.ttf'), {'FILL':0,'wght':400,'GRAD':0,'opsz':24}).save('material_symbols_rounded.ttf')"
```

## D-030 · 2026-10-01 · 번역 속도 · 정확도 추가 개선 (NA-09 · NA-10 · NA-11, 이슈 #19)
- **자동 모드 인식기는 단계적으로**: 직전 승자(처음은 한국어) 하나로 먼저 읽고, 결과가 미덥지 않을 때(`OcrSelection.isTrusted`: 글자 12자 미만 · 글자 가중 평균 신뢰도 0.8 미만 · 아무것도 못 읽음)만 나머지 한중일 인식기를 추가로 읽어 `pickBest`. 한 인식기가 라틴 글자도 읽으므로 영어 화면은 1개로 끝난다. **정확도 트레이드오프**: 한 화면에 첫 인식기가 못 읽는 문자 체계가 *일부만* 섞이고 나머지는 또렷하면(예: 한국어 화면 한쪽에 일본어 한 줄) 그 일부를 놓칠 수 있다. 전체가 다른 문자 체계이면 자동으로 걸러져 같은 결과를 얻는다.
- **인식 결과 재사용**: 입력 이미지(1280px로 줄인 것) 전체를 2px 간격 샘플로 해시해 직전과 같으면 인식을 건너뛴다. 시계 · 애니메이션이 있으면 달라서 재사용되지 않는다(정확도 영향 없음).
- **번역 결과 캐시**: ML Kit 엔진에 (글자, 원문, 대상) 키 LRU 128개. 모델이 지워진 직후에도 같은 글자는 캐시된 번역을 낸다(다음 번역 때 갱신).
- **블록 묶기 · 잡음 제거**: 번역 전에 `OcrCleaner`(글자 없는 줄 제거) → `OcrBlockMerger`(이어지는 블록을 문단으로). 보수적 기준(상수는 `OcrBlockMerger`)이라 못 묶는 쪽으로 틀린다. 묶인 블록은 화면 자리(bounds)가 합쳐진 사각형이라 '원문 위에 덮기'에서 한 막으로 덮인다.
- **언어 판별 보정**: 글자의 30% 이상이 한글이면 ko, 가나면 ja로 정해 Language ID 결과보다 우선(`LanguagePlan.scriptLanguage`). Language ID는 한자 많은 일본어를 zh로 읽는 일이 있다.
- 검토 후 안 한 것: 하나의 인식기 + 문자 체계 사전 판별(OCR 없이는 불가), 기기 내 모델 사전 내려받기 변경(이미 #11에서 예열), 입력 더 줄이기(작은 글자 인식률 저하).

## D-029 · 2026-10-01 · 빠른 언어 편집과 원문 위에 덮기 (FL-04 · NA-22, 이슈 #17)

- **원문 위에 덮기**: 결과 항목마다 원문의 화면 위 자리(`TranslatedItem.bounds`, 화면 대비 비율)를 들고 있다. 문자 인식 좌표는 (영역 캡처면 잘린 이미지 기준이라) 잘라낸 위치를 더해 전체 화면 비율로 바꾼다. 표시는 전체 화면 창에 항목마다 반투명 검정(78%) 상자를 깔고 흰 번역문을 상자에 맞는 가장 큰 크기(22~8sp)로 그린다. 화면 어디를 눌러도 닫힌다(복사 · 전체 복사는 없음 — 목록 · 문단 표시에서). 번역된 항목 중 자리를 아는 게 없으면 목록 시트로 대체한다.
- 번역하지 못한 · 미지원 블록은 덮지 않고 원문을 그대로 둔다.

## D-031 · 2026-10-01 · 덮어쓰기 글자 크기 일관화 · 인식 누락 줄이기 (NA-09 · NA-10 · NA-22, 이슈 #21)

## D-032 · 2026-10-01 · 자동 번역 — 화면이 바뀌면 알아서 다시 번역 (NA-26, 이슈 #23)
- **설정 "자동 번역"**(설정 탭): 기본 **꺼짐**. 켜면 화면 확인 간격(1 · 2 · 3 · 5초, 기본 2초)과 멈춘 뒤 기다리는 시간(0.5 · 1 · 1.5 · 2초, 기본 1초)을 고른다. 열 · 배터리를 쓰는 기능이라 사용자가 조절하게 했다. 저장은 DataStore, Flutter와는 Pigeon(`autoTranslate` · `autoCheckIntervalMs` · `autoSettleMs`).
- **시작**: 플로팅 버튼으로 번역한 결과가 화면에 오른 뒤부터 감시한다 (같은 영역 · 같은 설정으로). 켜기만 해서는 아무것도 돌지 않는다. 명세의 "고정 영역 주기 캡처"보다 범위를 넓혀 전체 화면 · 드래그 영역도 따라간다.
- **가벼운 변화 감지**: `ScreenCapturer.captureSignature`가 가장 최근 프레임 버퍼에서 64×128 격자 칸마다 한 픽셀의 밝기만 읽는다(비트맵 변환 · 인식 없음). 밝기가 24 넘게 다른 칸이 0.5% 이상이면 "뚜렷이 바뀜"(시계 · 커서 정도는 무시). 화면이 안 바뀌면 프레임도 안 오므로 정지 화면의 비용은 격자 읽기뿐.
- **안정 후 번역**: 바뀐 상태가 설정한 대기 시간 동안 더 변하지 않아야(스크롤이 멈춰야) 번역한다. 마지막 번역으로부터 3초 이상 지나야 한다(연속 번역 방지). 스크롤 중에는 따라가지 않고 멈춘 뒤 갱신한다.
- **기준 화면**: 번역 직후가 아니라 한 박자(0.7초) 뒤 첫 지문을 기준으로 삼는다 (결과 막이 뜨며 화면이 바뀌는 것을 변화로 오해해 무한 번역하는 것을 막는다).
- **간격 늘리기**: 변화가 없으면 15번 뒤 2배, 40번 뒤 4배(최대 8초). 바뀜을 기다리는 중에는 설정 간격.
- **캐시 재사용**: 새로 번역하면 인식 결과 재사용(D-030) · 번역 캐시(D-030)가 그대로 적용된다. 결과 항목이 직전과 같으면 결과 창을 바꾸지 않는다(깜박임 없음).
- **캡처에 결과가 찍히지 않게**: 자동 번역을 찍는 동안 떠 있는 결과 창과 버튼을 잠깐 숨긴다 (숨김은 캡처 순간까지만).
- **'원문 위에 덮기' 터치 통과**: 자동 번역 중의 덮기 막은 `FLAG_NOT_TOUCHABLE`로 아래 앱을 그대로 스크롤할 수 있게 하고, 닫기는 플로팅 버튼 탭(감시도 멈춤). Android 12+는 불투명 오버레이가 아래 앱 터치를 막으므로 창 알파를 시스템 허용 최대치(`maximumObscuringOpacityForTouch`, 기본 0.8)로 낮춘다. **대가: 막 · 글자가 약간 옅어진다.** 목록 · 문단 결과는 화면을 덮는 모달이라 터치 통과 없음(감시는 하되 닫으면 멈춤).
- **멈추는 때**: 결과를 닫음 · 버튼으로 다시 번역 · 서비스 종료 · 화면 꺼짐 · 절전 모드 변경 · 설정에서 끔. 번역할 글이 없어지면(글 없음 · 이미 대상 언어) 낡은 결과를 걷고 감시는 계속한다. 보안 화면 · 실패는 결과를 그대로 둔다.
- 검토 후 안 한 것: 별도 서비스 · 접근성 이벤트로 변화 감지(D-002), 화면 해시 전체 비교(읽는 양 많음), 스크롤 중 실시간 추적(OCR 반복 · 열).

## D-033 · 2026-10-01 · 버블 메뉴 '설정' · 빠른 언어 2열 (이슈 #27)
- 버블 4번째 '설정'은 지금 자동 번역 켜기 · 끄기만 둔다(항목은 나중에 추가). 인식 언어는 설정이 아니라 **빠른 언어** 메뉴에서 고른다.
- 빠른 언어 메뉴: 왼쪽 "번역할 언어"(자동 + 빠른 언어 목록, 문자 인식에 쓰는 `source_language`), 오른쪽 "번역될 언어"(대상 언어). 고른 뒤에도 열려 있고 바깥을 누르면 닫는다.

## D-034 · 2026-10-01 · 자동 번역 반응성 — 이전 결과 숨김 · 바로 번역 · 번역 중 취소 (NA-26, 이슈 #29)

## D-036 · 2026-10-01 · 표시 시점 · 숨김 일반화 · 블록 캐시 (NA-26, 이슈 #35)

- 덮어쓰기: 시간을 정하면 막지 않고 화면이 움직인 뒤 닫힌다. 직접 닫기(-1)이고 자동 번역이 꺼져 있으면 화면 전체를 막고 닫을 때까지 둔다(자동 번역이 켜져 있으면 스크롤하며 쓰는 흐름이라 막지 않는다).
- 자동 번역도 덮어쓰기일 때만 쓴다. 다른 표시일 때는 설정 · 메뉴에서 비활성이고 네이티브가 꺼진 것으로 다룬다(저장 값은 그대로).
- 설정 UI는 값을 바꾸지 않고 비활성으로만 보인다.

## D-045 · 2026-10-03 · 번역 취소 · 화면 이동 시 중지 · 로딩 표시 · 막 창 유지 (NA-12, NA-22, 이슈 #80)
- 번역 중 플로팅 버튼을 누르면 번역을 취소한다(코루틴 취소). 취소하면 로딩 · 일부 결과를 걷는다.
- 일반(수동) 번역도 캡처 뒤 화면이 움직이면 취소한다(자동 번역과 같은 규칙). 화면 지문(`FrameSignature`)을 250ms마다 보되, 우리 로딩 표시 · 일부 결과가 올라오면 지문이 바뀌므로 그때마다 700ms 쉬고 기준을 다시 잡는다. 버튼의 도는 호도 조금 잡히므로 기준을 바뀐 칸 4%로 넉넉히 둔다. 로딩 깜빡임 진폭(알파 0.2~0.34)도 지문 밝기 기준(24) 아래로 둔다.
- 덮어쓰기에서 OCR이 찾은 글자 자리를 번역 전에 먼저 연한 초록 막 + 테두리로 보여 주고, 번역이 끝난 블록부터 번역문으로 바꾼다(`TranslationPipeline.run(onPending)`). 언어 감지 뒤 번역할 블록만 보여, 건너뛸 글자에 로딩이 뜨지 않는다.
- 검은 창 깜빡임 원인 추정: 중간 결과마다 전체 화면 막 창을 지우고 새로 만들어 새 창 첫 프레임이 검게 비쳤다. 같은 종류 창이 떠 있으면 내용만 바꾼다. 번역 중 중간 막은 항상 터치 통과로 만들어, 끝날 때 한 번만 창이 바뀐다.

## D-046 · 2026-10-04 · 결과를 닫아도 자동 번역은 이어진다 (NA-19, 이슈 #82)
- 닫기는 지금 결과만 걷는다. 자동 번역을 끄는 것은 메뉴 · 설정 토글뿐이다 (D-044의 '직접 닫기 + 자동 번역' 흐름을 보완).
- 닫은 뒤 감시를 다시 걸어(`arm`) 막이 걷힌 화면을 새 기준으로 삼는다. 기준을 다시 잡지 않으면 막이 사라진 변화를 화면 변화로 보고 닫자마자 다시 번역해 결과가 되살아난다.

## D-047 · 2026-10-04 · 자동 번역이 켜져 있으면 직접 닫기 사용 불가 (NA-19, FL-06, 이슈 #86)

## D-049 · 2026-10-06 · AI 번역 설정: 연령 확인 · 말투 · 용어집 (FL-09, FL-11, 이슈 #118)
- Notion 명세(연령 확인: 처음 켤 때 만 18세 확인 · 저장 · 미확인이면 AI 엔진 선택 불가 / AI 옵션: 말투 존댓말 · 반말, 용어집 추가 · 삭제, 데이터 전송 고지)를 AI 번역 설정(S-06)에 넣었다.
- **연령 확인은 스위치 하나**(`ageConfirmed`, DataStore). 켜기 전에는 키 입력 · 옵션을 숨기고 엔진 선택을 막는다. 끄면 엔진을 ML Kit으로 되돌린다. 막는 곳은 네 군데다: Flutter `EngineViewModel`, 네이티브 `SettingsRepository.setEngine`(플로팅 버튼 메뉴 포함), 설정 읽기(`toSettings`가 확인 전 저장값 GEMINI를 ML Kit으로 본다), 서비스 엔진 선택. 이전 버전에서 이미 Gemini를 쓰던 사용자는 업데이트 뒤 한 번 확인해야 AI 번역이 다시 켜진다(저장값은 그대로라 확인하면 복원).
- **말투**는 기본(지정 안 함) · 존댓말 · 반말 세 가지. 프롬프트에 "polite/casual speech level" 문장을 덧붙인다. 대상 언어에 높임말이 없으면 효과가 작다고 화면에 안내한다.
- **용어집**은 원문 → 번역어 쌍, 최대 50개 · 각 60자. 같은 원문(대소문자 무시)은 하나만, 다시 넣으면 번역어를 바꾼다. 저장 형식은 DataStore 문자열(JSON). **번역할 글에 나온 항목만** 프롬프트에 넣어 요청을 작게 유지하고 불필요하게 용어를 내보내지 않는다.
- 말투 · 용어집은 `TranslationRequest.style`로 AI 엔진에만 전달하고, **번역 캐시 키에 들어간다**(옵션을 바꾸면 옛 번역이 나오지 않게). ML Kit일 때는 비워 캐시가 쪼개지지 않는다. `PROMPT_VERSION` 2.
- 데이터 전송 고지는 연령 확인 바로 아래에 항상 보인다(확인 전에도). 문구: 화면에서 읽은 글자가 AI 제공자(Google Gemini)로 전송, 무료 등급은 구글이 검토에 쓸 수 있음.
- 텍스트 선택 번역(NA-24)은 ML Kit만 쓰므로 영향 없음.
